# 版式与反例（tracking-doc-format 附属）

主文件只在「逐条出段」与「全篇输出」时按本文写；版式细节全在这里，主文件不重复。

## 输出样例与缩进

每个逻辑块**独占一行**；块与块之间**必须空一行**。禁止把多段拼进同一段落。

**加粗是硬要求**：埋点名、`**上报时机:**`、`**参数:**`、每个 `**参数名**` 必须用成对的 `**`（ASCII），不得用单反引号 `` `pdp_xxx` `` 代替标题或参数名。本 skill **不受** User Rules「加粗 ≤5 处」限制。

**分割线**：只在**全篇**输出时出现——段末下一行必须是且仅是 `-----------`，上下各空一行，全文禁止省略；**逐条核对阶段单段输出不带分割线**。

**缩进（Cursor 对话必用列表，否则看不见层级）**：在 `**参数:**` 下每个参数两条列表项——

```
**show_card**（卡片曝光）

**上报时机:** 卡片可见时上报，同一页面内不重复上报，刷新页面重置上报逻辑

**参数:**

- **module_name**: string类型。选择当前卡片后端下发的 title 来作为参数

  - 取值：product.title（product_detail_v3_model.dart:134）

- **rank**: int类型。当前的位置，从1开始。

  - 取值：_photoIndex + 2（pdp_video_header.dart:737）

- **上报点**：pdp_video_header.dart:737；未实现写 待新增（F1 讲解视频曝光入口）

-----------

（全篇里的下一段…）
```

- 列表：参数行用 `- **name**: 类型。说明`；取值行用空一格的 `  - 取值：…`（2 个空格 + `-`），**单独一行**，格式 `取值：<表达式>（<文件>:<行>）`；多来源用 ` / ` 分隔。
- 每段末尾一行 `- **上报点**：<文件:行>` 或 `- **上报点**：待新增（<功能点 / 入口>）`；它与参数行同级、不加缩进。
- 不用纯空格缩进代替列表（Cursor 对话里空格缩进常被吞掉）。
- 说明缺失时只写类型，不留空冒号；上报时机原文为空时写 `上报时机:未注明`。
- 参数顺序、埋点顺序按原文，不排序、不去重同名不同义的参数。

## 强调（不用颜色）

终端和对话通道都不支持给文字上色（裸 ANSI 的 ESC 会被剥掉，HTML span 会原样显示），所以全文只用加粗拉开层次，不要写颜色、不要写 span、不要写 ANSI：

- 埋点名：加粗，独占一行
- 「上报时机:」「参数:」：加粗标签本身
- 参数名：加粗

落盘的 `.md` 与对话正文使用**同一套**纯加粗 Markdown，不引入 HTML。

## 反例（禁止）

下面这种是**错误输出**，不得出现：

- 整行只有 `` `pdp_video_watch_end` `` 或 `pdp_video_watch_end`，没有 `**pdp_video_watch_end**`
- `上报时机:`、`参数:`、`product_id:` 未加粗，或与说明糊在同一段落里
- 段与段之间没有 `-----------`
- 用反引号高亮参数名，代替 `**product_id**`
- 取值与参数挤在同一行、无 `  - 取值：` 子项

## 发出前自检（正文写出前在心里过一遍）

1. 每个事件名是否都是 `**event_key**`（可带中文括号说明）？
2. 是否每两段埋点之间都有 `-----------` 且上下空行？
3. 每个参数是否都有 `- **param**:` 与 `  - 取值：` 两行？
4. 每段是否有 `- **上报点**：`？
5. 是否没有用代码围栏包住全文？
6. 逐条阶段是否**只**有当前一个埋点、结尾停在等用户确认（没顺手带出下一条、没提前给全篇）？
7. 进度行是否带已确认 / 跳过 / 待定计数，跳过项点名到 key？
8. 有没有写颜色、span、ANSI、单反引号当标题？
