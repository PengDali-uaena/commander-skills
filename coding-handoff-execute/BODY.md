# coding-handoff-execute

只执行已经写好的 Handoff。不重新设计。

## 边界

- 只改 Handoff「文件」和「步骤」点名的内容。改前用 read 工具 读该文件，改动用 edit / write，命令用 bash，多步进度用 步骤清单。
- 不新增步骤里没有的文件、依赖、行为或重构。
- 「仓库」在当前会话工作区外时，先说清并请用户批准放宽沙箱（workspace-write → danger-full-access）；被拒就停，不要静默失败。
- 不根据聊天记录补全 Handoff 里没有的决定。
- 用户要求改方案时，停止并说明改点名 `coding-handoff-plan`。

## 顺序

1. 消息里没有完整 Handoff：只回复「缺少 Handoff」，然后停止。
2. 检查字段是否齐全，顺序为：目标、仓库、约束、禁止、文件、步骤、验收、未决。
3. 任一字段为空，或「未决」不是「无」：只列出缺失项，然后停止。
4. 「仓库」目录不存在，或某一步的路径或符号对不上：引用该步骤，然后停止。不要全库搜索替代方案。
5. 按步骤序号修改。
6. 运行「验收」里的命令，并受目标仓库规则约束：该仓库 AGENTS.md / .cursor 规则禁止的命令（test / lint / 打包 / 碰设备）不跑，改为人工确认并写明原因。写着「无命令」时，跳过命令，只做其中能做的人工确认。
7. 回复按全局 AGENTS.md 的「结论 / 要点 / 下一步」三段写，正文 ≤ 220 字：改了哪些文件、验收结果、还有什么没做。

## 实现

- 按「约束」和「禁止」执行。
- 只读该步骤点名的文件。为实现该步骤，可以打开它直接引用的定义，读完即停。
- 步骤给出最小替换片段时，按片段替换。
- 步骤只写了结果、没有给出代码时，按该文件现有写法实现这个结果。

## 验收失败

- 失败是因为该步骤还没做到 Handoff 写的结果：只补这一步，再跑一次验收。
- 同一条命令连试 2 次仍失败：停手，把命令原文与输出交给用户。
- 失败是因为 Handoff 和代码事实冲突：停止，引用冲突的步骤和错误输出。不要改方案。

## Handoff 格式

```markdown
# Handoff
目标：<一句话结果>
仓库：<绝对路径>
约束：<必须遵守的限制>
禁止：<不要做的事>
文件：
- `<相对路径>`：<这个文件要变成什么样>
步骤：
1. <祈使句，一个动作>。改完结果：<可观察结果>
验收：
- 运行 `<命令>`，预期：<结果>
未决：无
```
