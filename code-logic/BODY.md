# code-logic

只讲代码怎么走。不加日志，不改文件。

用户只问文件路径、不问执行流程 → 不适用本 skill；由 commander 选 **file-locate**。

用户只要是否同一组件 / 同一套 UI / 同一实现，且未要求入口、挂载链、分支、流程 → 不适用本 skill；由 commander 选 **reply-brief**。

## 读代码

1. 用户给了路径、类名或函数名：只读这些，以及直接上下游各 1 层，最多 5 个文件。
2. 没给路径：最多 1 次定向搜索，关键词来自用户描述，再读不超过 3 个文件。禁止全仓乱扫。
3. 要日志、Tag 或筛选时，本 skill 不适用，改由 commander 选 bugfix-probe。用户本条显式点了 code-logic 时，仍然只讲不改。

## 递进

- **总结层（默认）**：第一行一句加粗结论——从哪进、最终产出什么；下面 2～4 句写主路径怎么走，全轮合计 ≤6 行，不逐条列接口。分支只概括成「有 N 处门控/异步点」，不逐条展开。支撑结论的最小路径可 inline 提及。若问题本身能用一句是/否答完，不要扩成多场景、多模块说明。文末最多一行：「要说展开分支我按入口/流程/关键分支逐条写」。
- **完整层**：用户说展开代码、展开分支、细化，或 commander 意图为完整层时，用下方「可见回复 · 完整层」。

## 可见回复 · 完整层

一行一个字段，按 commander「字段块版式」：都以 `- ` 开头，字段名加粗，字段之间不空行。符号和路径写全。不为了变短合并掉门控或分支。

```
- **入口**：谁触发，从哪进
- **流程**：步骤用 → 串起来
- **关键分支**：一个门控、分支或异步点
- **关键分支**：……
```

`- **关键分支**：` 有几处写几行，连续写、不空行、不缩进。用户问「哪容易错」时最后加一行 `- **易错**：`。

不写假设表，不写修复方案，不贴代码块。

## 示例（完整层形状）

```
- **入口**：打开直播间 → CommentList.refresh
- **流程**：拉黑名单 → ready=true → 按 blocked 过滤列表
- **关键分支**：ready 之前列表被清空
- **关键分支**：未登录仍会请求；请求失败则 ready 一直为 false
```
