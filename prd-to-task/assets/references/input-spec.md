# 输入规范（给提需求的人看）

这份是**你怎么给信息**的规范。技能侧已经能挡掉一部分（脚本闸门、骨架先行、档位），但下面四项只有你能给，缺一项就多一轮返工。

一页速查：

1. **结构先说**：层叠、谁滚谁固定、卡片顺序，用日常语言按顺序讲，不贴 node。
2. **节点列清单**：要落图的 node + 它属于哪一版帧，一次给全。
3. **变更加标签**：新增 / 改口径单独开一轮，写明「这是变更」。
4. **验收给动作**：每条写成「点什么 → 看到什么」，不写「正常展示」。
5. **开场核版本**：让我先报技能版本与脚本存在性；跨 agent 换新会话。
6. **一页需求别塞三个功能点**：>8 个功能点或 >20 个节点会按 L 档走（拆文档 + 实现另开会话）。

---

## 1. 结构（最省轮次的一条）

一份结构说明 = 层叠 + 滚动归属 + 固定区 + 卡片顺序。模板：

```text
最底层是渐变背景（满屏，非仅页顶）。
上层三部分：TitleBar / ScrollView / BottomBar。
- TitleBar：不随滚动移出；滚动位置 0 时透明（露出渐变），非 0 纯色；
- ScrollView：夹在 TitleBar 下方、BottomBar 上方；内容自上而下四张卡：商品信息卡 → 档位卡 → 填写信息卡 → 匿名卡；
- BottomBar：固定底部，不被键盘顶起；键盘盖在它上面。
横切：版心左右 12；白卡 r16；页面进入即黑色状态栏图标。
```

反例：只发三条 Figma 链接 + 「Implement this design from Figma」。模型只能自己推断层叠，推断错了就是「顶栏黑底」「submit 顶部白块」这类返工。

## 2. 节点清单（要落图才需要）

```text
fileKey：<...>；版本帧：评论填写 2.0（8699:33586）
要落图：五档表情 5 个（8699:33609 / 33613 / 33617 / 33621 / 33625）
示例图 2 个（8773:8439 / 8773:8443，在另一帧 Example photo 下）
不落图：竖线、选中圆底（本地画）
```

三件事必须写清：**属于哪版帧**（同一稿常有多版，混帧会落到不存在的 UI）、**哪些不落图**（避免把文案当图标切）、**示例图这类整张截图要不要透明底**（根上不透明，只能标 `opaque` + 代码 clip 圆角）。

## 3. 变更（第二轮最容易踩）

新增能力、改口径、改默认值，单独一轮，开头一句 `【变更】`，并说清三件事：

- 改的是哪一条（功能点编号或上一轮的原话）；
- 新的口径是什么；
- 旧的还要不要留（默认不留，正文只留一版）。

反例：「顺便把匿名开关默认关」写在别的回答里 → 文档正文两版并存，实现挑错一版（`F5c` 九分屏与 `I-003` 小数口径都是这么来的）。

## 4. 验收口径

| 好 | 坏 |
|---|---|
| 断网进页 → 卡片内显示错误文案 + Retry，点 Retry 只刷这张卡 | 接口失败时给个提示 |
| 提交中返回 → 不回滚、不拦截，回包后不再 toast | 返回逻辑按旧的来 |
| 五档点已选项 → 无响应，保持选中 | 重复点击要合理 |
| en / id 两种文案下角标都不被截断 | 注意多语言 |

判据：验收句里的每个动词都能在真机上点出来。

## 5. 会话与版本

- 开跑前说一句「报一下技能版本和脚本」，我回 `SKILL.md` 时间 + 两个脚本是否在盘上；
- 换 agent（Cursor ⇄ Pi）就新开会话，不接着旧会话改需求——磁盘上的技能更新不会进已开的会话；
- 一轮需求跑完再改技能，别在跑到一半时改，改了对当前会话无效。

## 6. 返工与输入缺口的对照

| 返工现象 | 你缺的是 |
|---|---|
| 顶栏黑底 / 卡片叠层 / 白块 | 结构（第 1 条） |
| 切图白底、尺寸不对、混帧 | 节点清单 + 哪版帧（第 2 条） |
| 文档新旧口径并存、改了三处漏一处 | 变更标签（第 3 条） |
| 「实现了但不像」反复调 UI | 验收口径 + 视觉规格由我逐区块写（第 4 条） |
| 明明说过又问一遍 | 我漏读台账——直接说「这个我第 N 轮答过了」，我按台账补 |

## 一句话总结

**你给结构和节点，我给规格和口径；你别给「正常展示」，我别留「待定」到最后。**
