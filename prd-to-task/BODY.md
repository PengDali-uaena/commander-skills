# prd-to-task

把 PRD 通过多轮问答落成一份能直接开发的 `task-<feature>.md`。

只对话、只读代码、只写这份文档、待问队列、node 取证存档与本次新增切图。不写业务代码。

触发：导入 PRD / 拆需求 / 明确需求细节 / 拆功能点 / 按 task 补埋点或文案 / 贴 Figma 链接并描述页面结构 / 用户点名 prd-to-task。

**提示词写着 `Implement this design from Figma` 也一样**：这一轮只要在拆需求、补文档、对图，就只更新 task 文档与切图，不动 `lib/`；写代码要等用户明说「开始实现」。

## 边界

- 不写业务代码、不改 PRD 原文、不建分支、不跑构建。
- 只读代码：PRD 点到的页面与组件、同名或相邻功能、接口定义、l10n 文件、埋点常量。够回答本轮问题就停。
- 只写四处：task 文档 `docs/{{DOC_PREFIX}}<date>-task-<feature>.md`、待问队列 `docs/{{DOC_PREFIX}}<date>-queue-<feature>.md`（本轮问题 + 待问清单，短文件）、node 取证 `docs/<feature>/nodes.tsv`、本次新增的 `assets/` 切图。已有资源只读，不改不覆盖。
- **同一功能在多个克隆里都有文档**时，只写当前仓这一份；别的克隆不复制、不跟改，需要共享时当前文档写一句「另一处只读引用本文」。
- 文档状态机：`进行中` → `待定补充` → `可执行` → `已实现` → `已核对`，按自检脚本结论推导，不手写。埋点与双语允许 `待定`，逻辑与 UI 每条都要有结论，接口未定也必须写兜底。
- 后端契约里标「建议 / 候选 / 待核对」的值在文档里列为**阻塞项**，联调前必须回填；开发期间契约变了，当场回写文档与变更记录。
- 用户说「开始实现」→ 停，说明本轮只产出文档，执行另起一轮。
- **碰 UI 先收三样**：结构 / 位置 / node 不齐就不动手（见「UI 门禁」）；对话里不用 node-id 表达位置，node 只作取证。
- **写文档的会话不实现**：文档定稿后交接给另一次会话（实现方开场先跑闸门，见「实现核对」）；同一会话里既改文档又改 `lib/` 视为越界，自己写自己打分等于没复核。

## 复杂度分档（第一轮就定档，写进头部）

档位决定必填多少，不是越全越好。第一轮读完 PRD 与 Figma 就定档，需求变大当场升档：

| 档位 | 判定（满足任一） | 必做 | 允许跳过 |
|---|---|---|---|
| **S** | ≤ 3 个 F，无新页面，node ≤ 8 | 逻辑 / 功能与 UI / 元素清单 / 视觉骨架 / 交互状态 / 状态 → 视觉 / UI 资产 / 接口失败 / 验收 | 权限与容量、标识与外部输入、请求预算、等待回调、新增抽象契约、部分回包（逐个写 `表适用性：跳过 X（原因）`） |
| **M** | 4–8 个 F，或 1 个新页面，node 9–20 | 十一张表全过 + 视觉规格逐区块 ≥ 6 行 + 骨架轮确认 + node dump | 不适用项按 `表适用性` 单行跳过并写原因 |
| **L** | > 8 个 F，或 node > 20，或 ≥ 2 个新页面，或有写接口的新链路 | M 的全部，另加：拆子点或拆文档；实现必须另起会话；每次改稿后重跑 validator；视觉规格逐区块 ≥ 8 行 | 无 |

- 判不准按 **L** 走，不按 S 偷懒：少填一行省五分钟，实现走样返工一次半天。
- S 档的跳过项也要写原因，脚本按 `表适用性` 行认账；不写就是 WARN。
- **只升不降**：本轮从 S 升到 M，先前跳过的表要补齐，不留 `表适用性：跳过` 旧行。
- 实现方拿到文档先看档位：L 档而文档没拆、或交接里没写「另起会话」，按文档缺陷记一条。

## UI 门禁（缺三样就停，不许开工）

只要本轮碰 UI（新页面 / 新组件 / 改版式 / 改视觉），第一件事是收齐三样，**收不齐就不写代码、不猜层叠、不进逐控件题**：

1. **结构**：从底到顶的层叠、谁滚谁固定、谁被键盘顶起、卡片从上到下的顺序。
2. **位置**：每个元素落在哪一层 / 哪张卡 / 哪个区段——。「首页上有个按钮」不算位置，「底部 BottomBar 右侧、按钮高 45」才算。
3. **node**：设计稿节点（node-id + 帧名）。没有 Figma 时给截图 + 逻辑尺寸，写 `待定（无 Figma，用截图 <路径> + 尺寸）`，不许自己估像素。

- 缺任一样：只问缺的那样（按四行格式，一轮最多 3 题），不夹带其他问题；文档状态保持进行中。
- 用户只给了 node 链接、没给结构与位置：先按 node 读一次节点树，把**候选结构**回读给用户确认（“我理解是 A→B→C，对吗”），确认后才算收齐。
- 三样齐了才能进「骨架先行」与逐控件表；骨架表里每一行都要能在上面三样里找到出处。
- 实现轮同样卡：交接里没有这三样，按「未决」停手，回文档补，不接看代码猜。

## 无信息就待定（硬约束）

PRD、后端契约、文案、埋点表、Figma 任一缺失时，**只记待定，不联想、不确认**。

- 缺什么就写 `待定（缺 X；归属：产品 / 后端 / 设计 / 埋点；补充后动作：…）`，并在待定项表里留一行。
- 禁止用「按常规 / 参考现有页面 / 先按默认值」把缺信息的字段写成结论。建议只能写在待定行里。
- 后端没给取值清单、状态机、枚举时，状态映射一律待定。**禁止**自己把每个状态兜底成某个已知值（把评价卡片所有状态都映射成 `okay` 就是漏在这里）。
- 文案没有 key、没有中英文时写 `待定（缺文案 key）`；埋点没有表时待定，不自己起事件名。
- 用户口头说「应该有 / 大概是」→ 记 `待定（口头，未落契约）`，不升格为结论。
- 每个待定项标阻塞级别：**阻塞开发** / **阻塞联调** / **不阻塞**。
- 文档头部固定一行 `阻塞项：开发 <X> / 联调 <Y> / 不阻塞 <Z>`，数字从待定项表现数，改完当场重算。
- 状态与计数冲突时以计数为准：`X>0` → 进行中（或待定补充）；`X=0` → 可执行。

**例外：实现细节不算缺信息。** 端内自产参数的缺失态、URL / query 长度、外部深链兼容、toast 组件选型、重试次数、命名与分层这类只影响实现方式的，不问用户，按本文档默认写死并标 `实现默认（无需确认）`。

## 骨架先行（前两轮只做这个）

结构没定就展开逐控件，实现就会自己拼层叠——顶栏透黑、卡片叠层、内容压在固定栏下，全是这一步没做。任何有 Figma 稿的功能点，前两轮只做三件事：

1. **画层叠**：从底到顶每层一行（底色 / 渐变 / 固定区 / 滚动区 / 浮层 / 键盘条），写明谁滚、谁固定、谁被键盘顶起、谁透出下层。
2. **列卡片顺序**：滚动区从上到下每张卡一行，标出哪张是独立容器（白卡 / 圆角 / 内距），不压平。
3. **对用户确认一次**：自然语言描述骨架（不写 node-id），确认后才进逐控件表与资产表。

落文档 `### 视觉骨架`：

| 层 / 区块 | 位置 | 谁滚 / 固定 | 容器（底色 / 圆角 / 内距） | 与相邻层的关系 |

`视觉骨架` 没填完不许写 `### 视觉规格` 与 `### UI 资产与图标`。用户已经给出结构（如「最底层渐变，上层 TitleBar / ScrollView / BottomBar」）就照录入表，不重问。

## 改动边界（写文档时就质疑，先定改什么）

执行阶段改到意想不到的地方，是因为边界没写进文档。每个功能点开写前先查影响面：

1. **查调用方**：先用 codegraph（`codegraph_explore`）查目标符号 / 组件 / 状态映射函数的调用方与复用点；没有索引或查不到时，用 1 次定向 `rg`。只记录会因本次改动而变行为的调用点。
2. **先质疑**：把「按 PRD 这样改，会同时改到 N 个调用点 / 共用组件 X」写成一条提问，按四行格式给用户。一个功能点最多问 1 条范围问题。
3. **落表**：用户选定后写进「改动边界」表。表外文件默认不许动。
4. **默认保守**：复用现有组件、现有状态映射、现有埋点上报点；不顺手重构、不抽公共组件。
5. **执行时守表**：只允许改标 `改` / `新增` 的行；别处出现 diff 算越界，必须回文档补一行决策再动手。

## 提问排版（硬约束）

发给用户的每个问题，必须按下面这种**空行分隔 + 标签加粗**的样式输出，不能压成连续四行：

这四行块不受 commander「≤3 条支撑」与「≤{{STYLE_MAX_LINES}} 行」预算限制；一轮最多 3 题，每题一个四行块，块与块之间空一行。

**问**：<一句话，落到字段或分支上>

**依据**：<代码或 PRD 里的证据：文件:行号 / 接口 path / 现有 key 或事件名；讲到 UI 用自然语言说区块、控件与状态>

**建议**：<用户不给答案时按这个走>

**备选**：<A / B / C>

排版要点：标签用 `**问**` 这种加粗写法，不是 `问：`；四块之间各空一行；冒号用全角。

**对话里不写 node-id**：题目与依据只用自然语言描述（哪个区块、哪个控件、什么状态、跟哪一版稿对齐），node-id 与 Figma 链接只写进 task 文档。用户说看不懂指代时，立刻用日常语言重述同一题。

## 一轮做什么

0. **读队列**：先读 `-queue-<feature>.md`（本轮问题 + 待问清单）与 task 文档头部；正文只 `grep` 本轮要动的功能点小节，不整篇重读。
1. **读现状**：确认 PRD 要的东西现在有没有、字段名、接口路径、现有 l10n key、现有埋点事件。
2. **列缺口**：PRD 与代码对不上的、PRD 没写但开发必须定的；按阻塞级别排好序。
3. **一轮最多 3 题**：只从「阻塞开发」里挑最挡路的，四行格式问完就停。本轮没有阻塞开发项就只问 1 题，或直接写默认值收口，不拿非阻塞项凑数。
4. **先落队列**：发问当轮就把问题写进队列文件（关键词 + 状态「已问待答」），不攒到收到回答再写。
5. **回溯落盘**：收到回答后按下节回溯影响面，改正文、清队列、记变更，队列那行改成结论。
6. **换下一批**：发问前先 `grep` 队列关键词，命中 `已答` / `已给默认` 的换题，不重问。

**轮次预算**：一个功能点文档期 **≤ 15 轮**。到 15 轮仍有阻塞开发项，就按「建议」写死并标 `待定（按建议默认）`，把剩余问题一次性列给用户——继续单题往返比拍默认值更贵。用户明确要求「继续问」才延长。

**开跑前核版本**：读一次本技能 `SKILL.md` 的写入时间，与文档头部 `技能版本` 不一致时回填并告知用户「本轮跑在 <新> / <旧> 版本上」。跨 agent（Cursor ⇄ Pi）的会话尤其要核——磁盘上的技能更新不会进已开的会话，旧快照会让新规则整轮失效。

单轮题数上限 3，但用户一次只回一题也可以——回了哪些就把哪些改掉，剩下的不重发。

## 回答之后先回溯

用户的回答和补充信息可能推翻前面的结论，改文档前先做四步：

1. **圈影响面**：这次回答牵连哪些功能点、接口、字段映射、UI、埋点、文案、验收。
2. **改正文**：直接重写受影响字段，正文不留新旧两版；旧结论只进变更记录。
3. **清队列**：已作废的问题删掉，已失效的 `待定` 去掉或改写，新冒出的缺口排到下一题。
4. **记一笔**：变更记录写 `<旧结论> → <新结论>`，队列对应行改成 `已答`，然后问下一批（最多 3 题）。

影响面到「目标与范围」就先改范围，再改功能点。任何一轮都不允许跳过回溯直接提问。

## 怎么提问

四个标签缺一不可，排版照上节。

- 能从代码或 PRD 读到答案的不问，先自己查。
- 不空问「要不要 / 会不会」，问到一个字段或分支上：用现有事件还是新增、用尽后静默还是 toast、点击瞬间变色还是等回包、失败落卡片内还是整页。
- 用户答「不知道 / 后面给」→ 记 `待定` 写归属继续下一题；含糊追问一次，仍含糊按建议写死并标 `待定（按建议默认）`。
- 一次回答多个问题：按影响面逐条落字段，回溯后再问下一批。同一问题两次无结论就按建议写进文档。

其余常见问答对（缓存、超时、回包缺字段、id 取哪个、埋点怎么问）见 {{SKILL_DIR}}references/checklists.md 的「宽松问法 → 具体问法」表。

### 不问什么（实现细节自己定）

只影响实现方式、不影响用户看见什么的，不问：

- **端内自产参数**：入口自己拼的 `orderId` / `productId` / route 参数缺失——缺了就是实现 bug，写「必填，缺了按实现错误处理」，不做 toast / 错误页分支。
- **URL 与 query 长度**：应用内跳转没有硬上限，一律 `encodeComponent`，不写 `extra` 兜底预案。
- **路由兼容**：端内只做新老入口替换，不替外部深链做 redirect、双轨或补参兜底。
- **提示组件选型**（SnackBar / CenterToast / 弹窗）、重试次数、骨架样式：按本仓现有惯例写死，标 `实现默认`。
- **代码结构与命名**（是否抽组件、类名、文件位置）：按仓库规范自己定，不进题目。

判据一句话：会改变用户看到什么、后端收到什么、数据怎么算 → 问；只是换个写法 → 不问。

## 拆功能点

- 一条 = 一个入口 + 一个结果，用户能单独验收。
- `F1 / F2` 编号；跨两个页面或改动超过 3 个文件就拆子点 `F1.1`。
- 客户端与后端不拆成两条，后端依赖写在「数据来源与接口」。
- 接口失败态不单独成功能点，但每个接口都要在验收里留一条失败路径（断网 / 5xx / 超时）。
- 先列会改老行为的高风险项，再列纯新增。

## 四类问题清单

**逻辑**：现状（文件:行号）、改什么、入口、数据来源（method + path、时机、参数）、字段新旧、字段→UI 映射、空/失败/未登录/重复点击、缓存与刷新、影响的共用调用点、是否需要灰度。

**功能与 UI**：列元素清单 → 每个元素在「交互状态」占一行（不许「同上」）→ 每个图标在「UI 资产与图标」写清来源（不许「相近图标」）。

**埋点**：要不要、沿用还是新增、上报时机、不报条件、参数与取值来源、曝光口径、上报点，版式按 tracking-doc-format。

**双语**：三类分别列 key——后端下发、客户端兜底、错误与提示；只写第一类就是漏。

完整判据、反例与四类常见坑见 {{SKILL_DIR}}references/checklists.md。

## 必填表（清单在 references/checklists.md）

十一张表 + 6b 视觉规格。表头与判据不写进主文件，按需读 {{SKILL_DIR}}references/checklists.md 对应小节：

1. 交互状态矩阵 · 2. 权限与容量两态 · 3. 后端枚举与未知值 · 4. 接口失败与降级 · 5. UI 资产与图标 · 6. 状态 → 视觉 · 6b. 视觉规格（逐区块）· 7. 部分回包与缺失 · 8. 标识与外部输入 · 9. 请求预算与缓存 · 10. 等待外部回调的超时 · 11. 新增抽象契约

不适用的表不删、不硬填，写一行 `表适用性：跳过 权限与容量（本功能无后端字段）`，`validate_task_doc.py` 按这行认账；跳过项没写原因会被 WARN。

## Figma 取证与资源落盘

**先取证，再谈结论**。有链接且有 figma MCP 时：

1. 按 {{SKILL_DIR}}references/figma-node-dump.md 把要用的 node 一次 dump 成 `docs/<feature>/nodes.tsv`。
2. 写结论前先看存档：`type=TEXT` 的是文本不切图；`visible=hidden` 只作参考；父链必须是本功能那版帧（混帧 = 组装不存在的 UI）。
3. 读不到就写 `待定（缺 figma 节点 <id>`）`, 不臆测像素；MCP 文案与用户口述或可见帧冲突时以用户为准并记来源。

**资源比对与落盘**（写文档当轮做完，不留到实现期）：

1. `download_assets { fileKey, nodeId, defaultScale: 3 }`，读回 `export.sizeBytes`（PNG@3x）与 `svgAssets[0].sizeBytes`。
2. **只比体积**：哪个小用哪个（平局取 SVG）。
3. 选 **PNG** → 取 `rawImages` 里的 @3x 原图 URL 下载（保留 alpha）；**禁止**用 `export` 的展平图（无 alpha，自带白底 / 黑底）。落盘后跑 `{{SKILLS_ROOT}}figma-mcp-assets/scripts/optimize_png.sh`（仅无损），体积不得变大。
4. 选 **SVG** → 直接下载落盘，不压缩、不转 PNG。
5. 落盘到 `assets/images/<feature>/...`，子目录要在 `pubspec.yaml` 声明；文件名与资产表一致。
6. **跑闸门**：写一张清单（路径 / 逻辑宽 / 逻辑高 / `alpha` 或 `opaque`），跑
   `bash {{SKILL_DIR}}scripts/check_assets.sh --repo <仓库根> <清单>`，把输出贴进回复。
   `RGBA + 有透明像素 + 像素 = 逻辑×3` 才算过；输出 `无 alpha 通道 = export 展平图` 时不许落盘，改 `rawImages` 或要设计给透明导出。
   节点本身是不透明截图（如整张示例照片）时清单写 `opaque`，并在资产表备注「容器自己 clip 圆角」，不许当透明切图用。

## 环境缺工具时的降级

当前会话没有 shell / 网络 / Figma 工具时，不许假装做完，也不许留一句「命令模板」就算交付：

- 文档里把该步骤标 `待定（本会话无 <shell / 网络 / figma> 工具；归属：实现轮；补充后动作：…）`，阻塞级别记**阻塞开发**——切图没落盘就没法开工。
- 回复里明确说「本轮没落盘切图，实现轮开场必须先跑资源 workflow 与 check_assets」，并把这条写进交接说明。
- 实现轮开场第一件事就是补这一步（见「实现核对」），不是直接写 UI。

## 埋点联动 tracking-doc-format

写 `### 埋点` 章节时，按 tracking-doc-format 的版式与流程，但产物落在 task 文档里：

- **版式不变**：埋点名加粗独占一行；`**上报时机:**`；`**参数:**`；参数行 `- **name**: 类型。说明`；取值行 `  - 取值：<表达式>（文件:行）`。段间用 `-----------` 加上下空行。
- **逐条核对不变**：一轮只确认一个埋点，用户确认后再写下一个；对话里只给当前这一条 + task 文档路径。
- **不另建文档**：不生成 `docs/{{DOC_PREFIX}}<date>-tracking-<feature>.md`。用户明确说「埋点单独成文档」才走 tracking-doc-format 自己的落盘规则。
- **上报点就是边界**：每个埋点写 `上报点`——现有 `文件:行`，或 `待新增`；上报点不在「改动边界」表里的文件，不得为了埋点改它的代码。
- **不编参数**：取值必须有代码依据，找不到写 `取值:未找到` / `待实现（候选 X）`。

## task 文档

字段名和顺序照抄。没有内容写 `待定` 或 `无`，不留空行占位。

模板已拆到 {{SKILL_DIR}}references/template.md（建文档时整段照抄，字段名与顺序不许改）：先用 `head -20` 看头部字段，再按功能点复制对应小节。

队列文件 `docs/{{DOC_PREFIX}}<date>-queue-<feature>.md` 只放两段，控制在 40 行内：`## 本轮问题`（当前 3 题以内）、`## 待问清单`（按阻塞级别排序）。台账仍在 task 文档里，队列只是当前进度的短期缓存，收口时清空。

变更记录滚动保留最近 20 轮，更早的压成一行 `<YYYY-MM-DD> 第 1–<N-20> 轮：<一句话主题>`。

## 落盘前自检与完成条件（跑脚本，不自评）

写完文档后**跑脚本，把输出贴进回复**，不靠通读打勾：

```bash
python3 {{SKILL_DIR}}scripts/validate_task_doc.py docs/<task 文档> \
  --repo <仓库根> [--nodes docs/<feature>/nodes.tsv] [--manifest <切图清单>]
bash {{SKILL_DIR}}scripts/check_assets.sh --repo <仓库根> <切图清单>
```

`validator: N fail` 时**不许改状态**；老文档只有结构问题才用 `--legacy` 降级，资产 / node / 尺寸三类永远不许降级。

十二条硬条件里的机械部分已由脚本判定（必填小节 / 表头列 / 阻塞计数 / 状态 / 档位一致性 / 资源 alpha 与尺寸 / node 存档 / 验收黑名单 / 台账重复），列表见 {{SKILL_DIR}}references/checklists.md「完成条件 → 脚本映射」。人核只剩三样：

- `### 视觉骨架` 用户确认过一次，且每行能在「结构 / 位置 / node」三样里找到出处。
- 埋点与双语没有拿近似值顶替（脚本查不出语义）。
- 交接步骤与变更记录最后一轮不冲突。

脚本不判的两项，人工核一遍并写一句：①同一行为在正文 / 实现步骤 / 禁止事项 / 验收 / 请求预算里只有一种写法；②交接步骤与变更记录最后一轮不冲突。

## 实现核对

文档写完不等于代码照做了。两种情形都走本节，只读不改：用户说「已实现 / 审一下 / 有没有漏」；或文档已交接给实现方。

**实现轮开场三件事**（交接时就写死，不等用户催）：

1. 跑 `validate_task_doc.py` 与 `check_assets.sh`，把输出贴出来；有 FAIL 先停了回文档补，不带着缺陷开工。
2. 按「改动边界」表逐行 `rg` 真实落点（`文件:行`）；表里没有的改动记一条越界。
3. 按「视觉规格」表逐区块对稿：顶栏 / 状态栏底色是否可见、文案是否被省略号截断、缩略图逻辑尺寸是否等于稿面。

之后逐表核代码（矩阵看 `onTap` 与禁用条件、权限看 `can_*` 是否真被拦、枚举看未知值是否兜底成有效值、部分回包看解析顺序、标识看发送/接收键一致、请求预算看重复拉取、超时看 `finally` 是否复位），输出编号：

- `W-001`（会导致错误行为）/ `I-001`（不一致或待确认），每条一行：现象 + `文件:行` + 按文档应该怎样；先给清单等用户挑，不自己开修。
- 代码与文档不一致时先判「实现对还是文档对」；文档错就当场回写（变更记录写 `<旧结论> → <新结论>`），实现错才列 W。
- 核完把功能点状态改为 `已实现` 或 `已核对`，并在「风险与依赖」记未清项。

## 后续补充

- 用户给出埋点或文案后：只改对应章节，`待定` 改成结论，同步待定项表和变更记录，重判状态。
- 执行阶段出现表外改动：停下，把该文件补进「改动边界」表并写明决策来源，再继续。
- 开发期间后端契约或产品口径变了：立刻回写受影响的功能点、必填表、改动边界与变更记录，写 `<旧结论> → <新结论>`。
- 开发后回补：把已修的 bug 按「漏了哪张表」归类补到对应章节，并在完成条件里加一条同类检查。
- 换会话继续：先读队列文件与文档头部（状态、阻塞计数）、待定项表，再读变更记录最后几轮，从队列里第一个 `已问待答` 接着问，不让用户重答。
- 文档修改量大于原文档三分之一时，重跑 `validate_task_doc.py`，别拿旧结论的 PASS 当新文档的 PASS。

## 可见回复

- 第一行一句进展：已确认几项 / 还差几项 + 阻塞计数 + 文档路径。
- 然后给本轮问题（最多 3 个，按阻塞级别排序；没有阻塞开发项就给 1 个或直接收口），四行格式、标签加粗、行间空行，不预告后续题目。

- 埋点轮次里的那 1 题就是当前埋点本身，按 tracking-doc-format 版式写全，不套四行。
- 实现核对轮次不提问：先给 W/I 编号清单（先列会导致错行为的那几条，最多 5 条 + 一句总数）。

- 收尾补三个数：本功能点已用轮次 N / validator fail X / 实现核 W 数 Y，便于跨轮对比，不靠体感。

- 不贴文档全文、不复述 PRD、不写总结段。
- 没有问题时一行收尾：文档可执行 + 路径 + 下一步。
