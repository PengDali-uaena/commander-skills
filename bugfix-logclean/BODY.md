# bugfix-logclean

确认修好之后，收掉本轮诊断日志。先自己找到 Tag，再检索、判定、改仓库。

## 找 Tag

按顺序，找到就用，不先让用户去翻：

1. 本条消息里的 Tag。
2. 本对话，或用户贴来的 session-handoff 里的 `Tag：`。
3. 未提交改动里本次新增的诊断 Tag。包括 `Probe/`，以及 diff 里新出现的日志 Tag。

找出多个互不相关的 Tag：只问一句要收哪一个。一处都没有：写明搜过消息、对话和 diff，然后停止，不改代码。

## 检索

对每个 Tag 搜索该字符串和相邻的日志调用。未搜索不得声称没有日志。

旧日志只增加了参数、没有新的日志调用：不动。

## 处置

| 情况 | 动作 |
|---|---|
| 旧日志只加了参数 | 不动 |
| 为排查临时抬高的级别 | 恢复原来的级别 |
| 一次性对位置的新日志 | 删除该行，以及只为它存在的临时变量、import、Tag 常量 |
| 以后还要用来对时序或状态 | 保留，级别改为 debug。仓库有正式 Tag 规范时，改成那个 Tag |

不把应删的日志留在 info、warning、error。不删与这些 Tag 无关的日志。

用户说「只给方案不要改代码」时只列判定，不改文件。除此之外必须改仓库。

## 验证

改完先看仓库规范。规范禁止的测试、lint、打包、真机命令不跑。规范点名的类型检查可以跑。没有要求就在回复里写明未跑。

## 可见回复

一行一个字段，按 commander「字段块版式」：都以 `- ` 开头，字段名加粗，同类多行连续写不空行。写到文件就带 `文件:行`。没有发生的类别省略。不用代码围栏，块外不加文字。命中→不动 为一组；统计、验证 各自单独成行，前面空一行。

```
- **命中**：文件:行 | 摘要 | 新增或原有
- **命中**：……
- **删除**：文件:行 为什么删
- **降级**：文件:行 改成了什么级别
- **保留**：文件:行 为什么留
- **不动**：文件:行 只加了参数

- **统计**：已改 N 处，M 处未动
- **验证**：命令结果，或未跑的原因
```

命中、删除、降级、保留、不动可以各有多行。
