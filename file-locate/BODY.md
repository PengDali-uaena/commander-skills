# file-locate

回答「**哪个 / 哪一个文件**（或 Widget）」——默认只给**一条主路径**，不讲挂载链、不讲接口字段。

不加日志，不改文件（用户同条明确要求改代码时：先答路径，再改）。

## 读仓

1. 当前项目若有 `.agents/docs/reference/file-keyword-mapping.md`：先 读，命中则再打开对应文件确认符号/Widget 名。
2. 否则：最多 **2 次**定向搜索（关键词来自用户描述：页面名、卡片名、业务词），再读不超过 **3** 个文件确认「这就是 UI 实现文件」。
3. 禁止全仓乱扫、禁止为答题堆关联文件（model、sheet、response 解析等）除非用户追问。

## 可见回复 · 默认（总结层）

- **第一行**：相对仓库根的路径；可附 `→ ClassName` 半句（同一行）。
- **第二行（可选）**：仅当存在**易混**实现时写「不是 `…/other.dart`」（例如商详 vs checkout 各有一套寄售 UI）。
- **禁止默认输出**：挂载 Section 列表、数据 model、弹窗、API 字段、Trade-In 例外、多段小标题 bullet 清单。
- 文末最多一行：`要说挂载/引用链 code-logic 或让我展开。`

用户说「展开」「怎么挂的」「还有谁用」→ 本 skill 仍可先给主路径，再按 **完整层**（见下）或请 commander 改选 `code-logic`。

## 可见回复 · 完整层

用户明确要求展开引用/挂载时，在首行主路径之后，最多 **5 行** bullet：

- 每行：`角色（入口/包裹/数据）→ 路径`，不写接口 JSON 键名除非用户问了数据从哪来。

## 与 code-logic 的边界

- 只问「在哪」→ 本 skill。
- 问「怎么走、从哪进、分支」→ `code-logic`，不是本 skill。
